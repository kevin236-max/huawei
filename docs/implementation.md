# 并发径流预测实现计划

### 已确定的设计
- 主 agent 全程保持一个 Pi 会话及上下文，提出具体方法、调参和融合指令，选择已有候选；不编写候选。
- 最多启动三批 subagent，每批最多三个新 Pi 会话，各自独立 workspace、固定 12 核。480 秒为软截止，排入一次收尾指令；额外收尾上限默认 180 秒，受搜索总截止约束。主 agent 的决策次数不计入这三批。
- 主 agent 首次接收完整提示词，后续在原会话中追加新批次结果；最后一批结果后追加 `\n\n` 和最终提交指令，提交最终候选路径和参数。
- 主工作区使用持续可见的只读挂载，交付文件对主会话 UID 可读。主会话保留单份轨迹及所有输入，禁用自动上下文压缩；各 subagent 保持独立轨迹。
- 搜索总上限 3600 秒；正常选择已有验证候选，未选择则取全程验证最高者，另行限时最终测试。
- 直接复制方法命名的文件，最终 JSON 只包含路径、分数、参数和简短结论。
- 软截止保持模型输出、工具调用和评估服务运行；硬截止返回正式验证最佳，无成功提交则返回 solution 下最新 Python 文件并注明无结果。正常收尾可返回 file=null 的方案说明。
- 同一月度径流加载与评分逻辑适配乌江和其他任务；默认乌江 plus、H=3。
- 主角色和执行角色各一份 Markdown 提示词，另有一份软截止收尾提示词；main 决定方案和调参策略，subagent 执行；仅内部验证分数分析工具。
